# Invory · Регистри на активи

React, Vite и Tailwind CSS приложение за регистри, активи, подрегистри, покани, заявки и история. Интерфейсът е на български.

- [Обиколка на екраните](docs/frontend-sections.md)
- [API, обяснено с прости думи](docs/api-contract.md)
- [Точен технически договор](docs/openapi.yaml)

## Стартиране без backend

```sh
cp .env.example .env
npm ci
npm run dev
```

Отворете адреса, показан от Vite. По подразбиране `VITE_API_MODE=mock`: MSW стартира преди React и прихваща същите `/api/v1` заявки, които ще получава бъдещият сървър. Не е нужен ASP.NET Core процес. При промяна на `.env` рестартирайте Vite.

Приложението започва празно, като истински сървър в първия си ден. Създайте профил от екрана за вход; имейлът може да е измислен.

### Как да проверите целия процес

1. Създайте профил, който ще бъде администратор. Добавете регистър и актив.
2. В „Подрегистри“ създайте подрегистър, изберете актива и от „Покани профил“ генерирайте връзка. Копирайте я.
3. Натиснете „Изход“, отворете връзката и създайте втори профил. Приемете поканата.
4. Като участник натиснете „Свери“ и подайте промяна на местоположение.
5. Излезте, влезте като администратор и в „Заявки“ одобрете заявката. Активът и „История“ се обновяват.

За да работите с два профила едновременно, използвайте два раздела: всеки раздел помни свой вход.

### Къде се пазят тестовите данни

Данните се пазят само в този браузър, в `localStorage` под `invory.mock.database.v2`, и се споделят между разделите му. Различни браузъри и устройства не ги виждат; за това е нужен реалният backend. Входът на раздела се помни в `sessionStorage` под `invory.mock.user.v1` и се изчиства при „Изход“. Паролите се записват само като SHA-256 отпечатък.

За да започнете отначало, изчистете данните на сайта от настройките на браузъра или изпълнете в конзолата му `localStorage.removeItem('invory.mock.database.v2')` и презаредете.

## Реален API режим

Задайте в `.env`:

```env
VITE_API_MODE=api
VITE_API_BASE_URL=http://localhost:5000/api/v1
```

Ако frontend и backend са на един origin, използвайте `VITE_API_BASE_URL=/api/v1`. В `api` режим MSW не се стартира и няма връщане към тестови данни след API грешка. Преди публикуване на приложението задайте `VITE_API_MODE=api`, защото без тази настройка то стартира в `mock` режим.

Екранът за вход изпраща данните към `POST /auth/login` или `POST /auth/register`; отговорът трябва да съдържа `user`, краткоживеещ JWT `accessToken` и `expiresAt`. Клиентът пази access токена само в паметта и го изпраща като Bearer заглавка. Какво точно трябва да реализира ASP.NET Core е описано в края на [API ръководството](docs/api-contract.md#checklist-for-whoever-builds-the-server) и в [openapi.yaml](docs/openapi.yaml).

## Проверки и структура

```sh
npm test
npm run test:ui
npm run check:api
npm run lint
npm run build
```

За `npm run test:ui` дръжте Vite стартиран на `http://127.0.0.1:5173/` в mock режим и инсталирайте браузъра веднъж с `npx playwright install chromium`. Ако Vite използва друг порт, подайте адреса: `node scripts/smoke-ui.mjs http://127.0.0.1:5174/`. UI проверката работи в собствен празен браузърен профил.

`src/api/client.js` е общият HTTP клиент. `src/api/` съдържа модулите по ресурси и TanStack Query настройките. `src/mocks/` съдържа само локалния тестов сървър, неговата база и workflow тестовете му. Компонентите в `src/features/` правят заявки през API слоя; състоянието на сървърните данни се кешира по потребител, ресурс и филтър и се обновява след запис. `src/App.jsx` управлява маршрути, диалози и текущия профил. `public/mockServiceWorker.js` е генерираният MSW worker.

Архивирането запазва актива и историята; одобреното бракуване оставя запис със статус „Бракуван“. Това е временно договорено поведение до окончателното решение за backend модела.

# Invory · Регистри на активи

React, Vite и Tailwind CSS приложение за регистри, активи, подрегистри, покани, заявки и история. Интерфейсът е на български. REST договорът е в [docs/api-contract.md](docs/api-contract.md) и [docs/openapi.yaml](docs/openapi.yaml).

## Локално демо

```sh
cp .env.example .env
npm ci
npm run dev
```

Отворете адреса, показан от Vite. По подразбиране `VITE_API_MODE=mock`: MSW стартира преди React и прихваща същите `/api/v1` заявки, които ще получава бъдещият сървър. Не е нужен ASP.NET Core процес. При промяна на `.env` рестартирайте Vite.

Началният екран е вход в профила. В демо режим изберете някой от трите измислени профила; можете и да въведете посочения имейл с парола `demo`. След вход профилът може да се сменя от горната лента:

| Профил | Начален пример |
|---|---|
| Елена · Счетоводство (`accounting`) | Администратор на „Демо регистър“ |
| Иван · МОЛ (`custodian`) | Участник в „Каб. 302“ |
| Мария · Преглед (`viewer`) | Гост в „Каб. 302“ |

Създайте регистър и актив като Елена, после подрегистър и изберете актива в него. В „Покани профил“ генерирайте връзка за Участник или Гост. Копирайте я, изберете Иван или Мария и отворете връзката в същия браузър. Приемането добавя подрегистъра в „Поканени регистри“. Като Иван подайте промяна на местоположение или предложете бракуване; като Елена отворете „Заявки“ и одобрете или отхвърлете. Историята и данните на актива се обновяват от API отговорите. Гостът може да търси и преглежда, но не да променя записи.

„Нулирай демо данните“ в горната лента възстановява измислените начални данни. Демо базата се пази в `localStorage` под `invory.mock.database.v1` и се споделя между раздели със същия браузърен origin. Ако няма нова демо база, съществуващите регистри от стария ключ `invory.react.registry.v1` се импортират еднократно; старият ключ не се изтрива. Избраният демо профил се пази отделно за раздела в `sessionStorage` под `invory.mock.user.v1` и се изчиства при „Изход“. Независими браузъри и устройства не споделят тези данни; за това е нужен реалният backend. Демо режимът не пази реални пароли или токени за автентикация в браузърното хранилище; временният демо Bearer токен е само в паметта на страницата. Връзките за покана са измислени тестови токени в демо базата.

## Реален API режим

Задайте в `.env`:

```env
VITE_API_MODE=api
VITE_API_BASE_URL=http://localhost:5000/api/v1
```

Ако frontend и backend са на един origin, използвайте `VITE_API_BASE_URL=/api/v1`. В `api` режим MSW не се стартира и няма връщане към демо данни след API грешка. Екранът за вход изпраща имейл и парола към `POST /auth/login`; отговорът трябва да съдържа `user`, краткоживеещ JWT `accessToken` и `expiresAt`. Клиентът пази access токена само в паметта и го изпраща като Bearer заглавка. Backend задава HttpOnly refresh cookie при вход, подновява го чрез `POST /auth/refresh` при презареждане или изтекъл access токен и го изчиства при `POST /auth/logout`. Регистрацията има подготвен API договор и клиентски метод, но екранът за регистрация е следващ етап. ASP.NET Core трябва да реализира пътищата, схемите, статусовете, пагинацията, JWT проверките, refresh сесията и достъпа по обхват от договора. При различни origins backend трябва да разреши точния frontend origin и credentials чрез CORS и да настрои refresh cookie според HTTPS средата. Демо селекторът съществува само в `mock` режим.

## Проверки и структура

```sh
npm test
npm run test:ui
npm run check:api
npm run lint
npm run build
```

За `npm run test:ui` дръжте Vite стартиран на `http://127.0.0.1:5173/` в mock режим и инсталирайте браузъра веднъж с `npx playwright install chromium`. Ако Vite използва друг порт, подайте адреса: `node scripts/smoke-ui.mjs http://127.0.0.1:5174/`. UI проверката нулира демо данните в собствения си браузърен профил.

`src/api/client.js` е общият HTTP клиент. `src/api/` съдържа модулите по ресурси и TanStack Query настройките. `src/mocks/` съдържа само локалната тестова база, MSW handlers и техните workflow тестове. Компонентите в `src/features/` правят заявки през API слоя; състоянието на сървърните данни се кешира по потребител, ресурс и филтър и се обновява след запис. `src/App.jsx` управлява маршрути, диалози и текущия профил. `public/mockServiceWorker.js` е генерираният MSW worker.

Архивирането запазва актива и историята; одобреното бракуване оставя запис със статус „Бракуван“. Това е временно договорено поведение до окончателното решение за backend модела.
